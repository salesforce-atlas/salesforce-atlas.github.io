    📚 Fundamentals & Platform Basics¶

    Q: What is Salesforce's security model and how does it work?¶

    A: Salesforce's security model is a layered approach that controls access to data at multiple levels, from the organization down to individual fields and records.

    Security Layers:

    • Organization Level: Login access, password policies, network restrictions
    • Object Level: Determines which objects users can access via profiles and permission sets
    • Field Level: Controls visibility and editability of specific fields
    • Record Level: Determines which specific records users can view and edit through OWD, role hierarchy, and sharing rules

    Key Characteristics:

    • Uses a "least privilege" approach - deny access by default, grant explicitly
    • Multiple layers work together - most restrictive setting wins
    • Declarative configuration requires no code
    • Can be extended with Apex sharing for custom logic

    Security Model Hierarchy:

    1. Can user log in? (IP restrictions, login hours)
    2. Can user see this object? (Profile/Permission Set)
    3. Can user see this field? (Field-Level Security)
    4. Can user access this record? (OWD + Sharing Rules + Role Hierarchy)
    5. Can user perform this action? (CRUD permissions)

    Salesforce Edition Requirements:

    • ✅ All editions support basic security model
    • ✅ Professional Edition and above support role hierarchy
    • ✅ Enterprise Edition and above support advanced sharing rules

    Best Practices:

    • ✅ Start with restrictive OWD settings and open up as needed
    • ✅ Use permission sets for additive permissions
    • ✅ Regularly audit user access using Security Health Check
    • ✅ Implement field-level security for sensitive data
    • ✅ Test security with different user profiles

    Q: What is Organization-Wide Default (OWD) and how does it affect data access?¶

    A: Organization-Wide Default (OWD) is the baseline level of access that users have to records they don't own. It establishes the most restrictive settings for an object, which can then be opened up through role hierarchy, sharing rules, and manual sharing.

    OWD Sharing Settings:

    • Private: Only record owner and users above them in role hierarchy can access
    • Public Read Only: All users can view records but only owners can edit
    • Public Read/Write: All users can view and edit all records
    • Controlled by Parent: For detail records in master-detail relationships
    • Public Read/Write/Transfer: Available for Cases and Leads only
    • Public Full Access: Available for Campaigns only

    Key Considerations:

    • OWD can only be used to restrict access, never to grant additional access
    • Changes to OWD settings can take time to recalculate sharing
    • More restrictive OWD settings require more sharing rules
    • Cannot set OWD to Private for master objects in master-detail relationships

    Example Use Cases:

    • Sales Organization: Set Opportunities to Private so reps only see their own deals
    • Support Team: Set Cases to Public Read Only so all agents can view but only case owners can update
    • Marketing Department: Set Campaigns to Public Read/Write so all marketers can collaborate

    Configuration Steps:

    Navigate to: Setup → Security → Sharing Settings

    Governor Limits:

    ⚠️ OWD recalculation can take hours for large data volumes

    ⚠️ Defer sharing calculation option available for data loads

    Salesforce Edition Requirements:

    • ✅ Available in all editions
    • ✅ Private OWD requires Professional Edition or above for role hierarchy

    Best Practices:

    • ✅ Set OWD as restrictive as business requirements allow
    • ✅ Use "View All" and "Modify All" permissions sparingly
    • ✅ Test OWD changes in sandbox before production
    • ✅ Document business justification for OWD settings
    • ✅ Review OWD settings quarterly as business needs evolve

    Related Salesforce Features:

    • Role Hierarchy (opens access up)
    • Sharing Rules (opens access to groups)
    • Manual Sharing (opens access to individuals)
    • Territory Management (alternative to role hierarchy)

    Q: What is the difference between a Profile and a Permission Set?¶

    A: Profiles and Permission Sets both control user access in Salesforce, but they serve different purposes. Profiles define the baseline permissions every user must have, while Permission Sets extend those permissions for specific users without changing their profile.

    Key Differences:

    • Profile: Required for every user (one per user), defines minimum access level
    • Permission Set: Optional, can assign multiple per user, grants additional permissions only
    • Profile: Can both grant and restrict permissions
    • Permission Set: Can only grant additional permissions, never restrict

    When to Use Each:

    • Use Profiles for: Common baseline permissions shared by a group of users
    • Use Permission Sets for: Special access needs that only some users require
    • Use Permission Sets for: Project-based or temporary access requirements
    • Use Permission Sets for: Reducing profile proliferation

    Q: How do I configure Field-Level Security (FLS) in Salesforce?¶

    A: Field-Level Security (FLS) controls whether users can see and edit specific fields on an object. It works in conjunction with object-level permissions to provide granular data access control.

    FLS Permission Levels:

    • Visible: User can see the field (read access)
    • Read-Only: User can see but not edit the field
    • Hidden: User cannot see or edit the field (most restrictive)
    • Editable: User can both see and edit the field (requires Visible + Edit)

    Configuration Methods:

    Method 1: From Profile/Permission Set

    • Setup → Users → Profiles (or Permission Sets)
    • Select profile/permission set
    • Find "Field-Level Security" section
    • Click field name → Set permissions

    Method 2: From Field Settings

    • Setup → Object Manager → [Object] → Fields & Relationships
    • Click field name → "Set Field-Level Security" button
    • Configure for multiple profiles at once

    public class SecurityUtils {

    // Generic FLS checker
    public static Boolean checkFieldAccessible(String objectName, String fieldName) {
        Schema.SObjectType objectType = Schema.getGlobalDescribe().get(objectName);
        if (objectType == null) return false;

        Schema.DescribeSObjectResult describeResult = objectType.getDescribe();
        Map<String, Schema.SObjectField> fields = describeResult.fields.getMap();

        if (fields.containsKey(fieldName)) {
            return fields.get(fieldName).getDescribe().isAccessible();
        }
        return false;
    }

    // Check multiple fields at once
    public static Map<String, Boolean> checkFieldsAccessible(
        String objectName, 
        List<String> fieldNames
    ) {
        Map<String, Boolean> results = new Map<String, Boolean>();
        Schema.SObjectType objectType = Schema.getGlobalDescribe().get(objectName);

        if (objectType != null) {
            Map<String, Schema.SObjectField> fields = 
                objectType.getDescribe().fields.getMap();

            for (String fieldName : fieldNames) {
                if (fields.containsKey(fieldName)) {
                    results.put(
                        fieldName, 
                        fields.get(fieldName).getDescribe().isAccessible()
                    );
                } else {
                    results.put(fieldName, false);
                }
            }
        }
        return results;
    }
}

    Q: How do Role Hierarchies work and when should I use them?¶

    A: Role Hierarchy in Salesforce is a tree structure that defines levels of data access. Users at higher levels in the hierarchy can access records owned by or shared with users below them, implementing a "ladder of access" model.

    Core Concepts:

    • Upward Access: Users higher in hierarchy can access records of users below them
    • No Lateral Access: Users at same level cannot see each other's records (unless sharing rules permit)
    • No Downward Access: Users cannot see records of users above them
    • Applies When: OWD is set to Public Read Only or Private

    Role Hierarchy Components:

    • Role: Named position in hierarchy (e.g., "VP Sales", "Sales Rep")
    • Level: Depth in the hierarchy tree
    • Parent-Child Relationship: Defines reporting structure
    • User Assignment: Each user assigned to one role

    • Alternative: Use Territory Management for geographic sales organizations

    🔒 Security Models & Sharing¶

    Q: What are Sharing Rules and when should I use them?¶

    A: Sharing Rules are automated mechanisms to grant record access to users who wouldn't normally have access through OWD, role hierarchy, or ownership. They extend sharing beyond the organization-wide defaults.

    Types of Sharing Rules:

    • Criteria-Based: Share records matching specific criteria with groups of users
    • Owner-Based: Share records owned by specific users/groups with other users/groups

    Key Characteristics:

    • Can only open up access (never restrict)
    • Run automatically when conditions are met
    • Support up to 300 sharing rules per object
    • Recalculated when criteria changes or ownership changes

    6. Select who to share with
    7. Set access level (Read Only or Read/Write)

    • Read Only: View records only
    • Read/Write: View and edit records
    • Full Access: Available only for certain objects (Campaigns, Cases, Leads)

    public static void shareAccountsWithExecutives(Set<Id> accountIds) {
        // Get Executive group
        Group executives = [
            SELECT Id 
            FROM Group 
            WHERE DeveloperName = 'Executive_Team'

            System.debug('Sharing failed: ' + e.getMessage());
        }
    }

    public static void revokeAccountSharing(Set<Id> accountIds, Id groupId) {
        List<AccountShare> sharesToDelete = [
            SELECT Id 
            FROM AccountShare 
            WHERE AccountId IN :accountIds 
            AND UserOrGroupId = :groupId

    // Share opportunities with team members
    public static void shareWithTeamMembers(Set<Id> opportunityIds) {

        // Get opportunity team members
        List<OpportunityTeamMember> teamMembers = [
            SELECT Id, OpportunityId, UserId, TeamMemberRole
            FROM OpportunityTeamMember
            WHERE OpportunityId IN :opportunityIds
        ];

        List<OpportunityShare> sharesToInsert = new List<OpportunityShare>();
        Set<String> existingShares = new Set<String>();

        // Check existing shares to avoid duplicates
        List<OpportunityShare> existing = [
            SELECT OpportunityId, UserOrGroupId
            FROM OpportunityShare
            WHERE OpportunityId IN :opportunityIds
            AND RowCause = :Schema.OpportunityShare.RowCause.Team__c
        ];

        for (OpportunityShare share : existing) {
            existingShares.add(
                String.valueOf(share.OpportunityId) + '_' + 
                String.valueOf(share.UserOrGroupId)
            );
        }

        // Create sharing records for team members
        for (OpportunityTeamMember member : teamMembers) {
            String shareKey = String.valueOf(member.OpportunityId) + '_' + 
                            String.valueOf(member.UserId);

            if (!existingShares.contains(shareKey)) {
                OpportunityShare share = new OpportunityShare();
                share.OpportunityId = member.OpportunityId;
                share.UserOrGroupId = member.UserId;

                // Set access level based on role
                if (member.TeamMemberRole == 'Account Manager') {
                    share.OpportunityAccessLevel = 'Edit';
                } else {
                    share.OpportunityAccessLevel = 'Read';
                }

                share.RowCause = Schema.OpportunityShare.RowCause.Team__c;
                sharesToInsert.add(share);
            }
        }

        if (!sharesToInsert.isEmpty()) {
            Database.SaveResult[] results = Database.insert(sharesToInsert, false);

            // Handle errors
            for (Integer i = 0; i < results.size(); i++) {
                if (!results[i].isSuccess()) {
                    System.debug('Failed to share: ' + results[i].getErrors());
                }
            }
        }
    }

    // Remove sharing when team member is removed
    public static void removeTeamMemberAccess(Set<Id> opportunityIds, Set<Id> userIds) {
        List<OpportunityShare> sharesToDelete = [
            SELECT Id 
            FROM OpportunityShare 
            WHERE OpportunityId IN :opportunityIds 
            AND UserOrGroupId IN :userIds
            AND RowCause = :Schema.OpportunityShare.RowCause.Team__c
        ];

        if (!sharesToDelete.isEmpty()) {
            delete sharesToDelete;
        }
    }

    // Recalculate all sharing (use sparingly)
    public static void recalculateSharing(Set<Id> opportunityIds) {
        // First remove all existing Apex managed shares
        delete [
            SELECT Id 
            FROM OpportunityShare 
            WHERE OpportunityId IN :opportunityIds
            AND RowCause = :Schema.OpportunityShare.RowCause.Team__c
        ];

        // Then recreate shares
        shareWithTeamMembers(opportunityIds);
    }

    Q: What is Shield Platform Encryption and when should I use it?¶

    A: Shield Platform Encryption is an advanced security feature that encrypts data at rest at the application layer using a customer-controlled encryption key. Unlike standard encryption, Shield encryption protects sensitive data with keys that customers can manage and rotate.

    Key Concepts:

    • Data at Rest: Encrypts stored data in Salesforce databases
    • Application-Layer Encryption: Encrypts before data is written to database
    • Customer-Managed Keys: Organizations can bring their own encryption keys
    • Key Hierarchy: Tenant secret, master secret, and data encryption keys
    • Field-Level Encryption: Encrypt specific fields on standard and custom objects

    // Download and parse log file content
    public static String getLogFileContent(Id logFileId) {
        EventLogFile logFile = [
            SELECT LogFile 
            FROM EventLogFile 
            WHERE Id = :logFileId
        ];

        // LogFile is a ContentVersion, need to query the file
        ContentVersion cv = [
            SELECT VersionData 
            FROM ContentVersion 
            WHERE Id = :logFile.LogFile
        ];

        Blob fileData = cv.VersionData;
        String csvContent = fileData.toString();

        return csvContent;
    }

    // Parse CSV log data
    public static List<Map<String, String>> parseLogFile(String csvContent) {
        List<Map<String, String>> records = new List<Map<String, String>>();
        List<String> lines = csvContent.split('\n');

        if (lines.isEmpty()) return records;

        // First line is header
        List<String> headers = lines[0].split(',');

        // Parse data rows
        for (Integer i = 1; i < lines.size(); i++) {
            List<String> values = lines[i].split(',');
            Map<String, String> record = new Map<String, String>();

            for (Integer j = 0; j < headers.size(); j++) {
                if (j < values.size()) {
                    record.put(headers[j], values[j]);
                }
            }
            records.add(record);
        }

        return records;
    }
}

    // Detect potential brute force attacks
    public static List<String> detectBruteForceAttempts() {
        List<String> suspiciousUsers = new List<String>();

        // Get recent login event logs
        List<EventLogFile> logs = EventMonitoringService.getLoginLogs();

        Map<String, Integer> failedAttempts = new Map<String, Integer>();

        for (EventLogFile log : logs) {
            String content = EventMonitoringService.getLogFileContent(log.Id);
            List<Map<String, String>> records = 
                EventMonitoringService.parseLogFile(content);

            for (Map<String, String> record : records) {
                String username = record.get('USER_NAME');
                String status = record.get('LOGIN_STATUS');

                if (status == 'LOGIN_INVALID_PASSWORD' || 
                    status == 'LOGIN_CHALLENGE_FAILED') {

                    Integer count = failedAttempts.get(username);
                    count = (count == null) ? 1 : count + 1;
                    failedAttempts.put(username, count);

                    // Alert if more than 5 failed attempts
                    if (count > 5) {
                        suspiciousUsers.add(username);
                    }
                }
            }
        }

        return suspiciousUsers;
    }

    // Track unusual access patterns
    public static void detectAnomalousAccess() {
        // Get login logs
        List<EventLogFile> logs = [
            SELECT Id, EventType 
            FROM EventLogFile 
            WHERE EventType = 'Login'
            AND LogDate = TODAY
        ];

        Map<String, Set<String>> userAccessPatterns = 
            new Map<String, Set<String>>();

        for (EventLogFile log : logs) {
            String content = EventMonitoringService.getLogFileContent(log.Id);
            List<Map<String, String>> records = 
                EventMonitoringService.parseLogFile(content);

            for (Map<String, String> record : records) {
                String username = record.get('USER_NAME');
                String sourceIp = record.get('SOURCE_IP');
                String loginTime = record.get('TIMESTAMP');

                // Track IP addresses per user
                if (!userAccessPatterns.containsKey(username)) {
                    userAccessPatterns.put(username, new Set<String>());
                }
                userAccessPatterns.get(username).add(sourceIp);

                // Alert if user logs in from more than 3 different IPs in one day
                if (userAccessPatterns.get(username).size() > 3) {
                    sendSecurityAlert(username, userAccessPatterns.get(username));
                }
            }
        }
    }

        // Send alert email or create case

        System.debug('Failed login: ' + event.Username + 
                    ' from IP: ' + event.SourceIp);

        // Check for brute force pattern
        Integer recentFailures = countRecentFailures(event.Username);

        if (recentFailures > 5) {
            // Lock user account or send alert
            freezeUser(event.UserId);
        }
    }

    private static void validateSuccessfulLogin(LoginEventStream event) {
        // Check for impossible travel
        // (login from two distant locations in short time)

        LoginHistory lastLogin = getLastLoginLocation(event.UserId);

        if (lastLogin != null) {
            Double distanceKm = calculateDistance(
                lastLogin.CountryIso,
                event.CountryIso
            );

            Long minutesBetween = calculateMinutes(
                lastLogin.LoginTime,
                event.LoginTime
            );

            // If travel would require > 1000 km/hr, flag as suspicious
            if (distanceKm / (minutesBetween / 60.0) > 1000) {
                sendImpossibleTravelAlert(event.UserId, event.Username);
            }
        }
    }

    private static Integer countRecentFailures(String username) {
        // Count failed logins in last hour
        DateTime oneHourAgo = DateTime.now().addHours(-1);

        return [
            SELECT COUNT()
            FROM LoginHistory
            WHERE LoginTime >= :oneHourAgo
            AND Status = 'Failed'
            AND Username = :username
        ];
    }

    private static void freezeUser(Id userId) {
        User u = new User(Id = userId, IsActive = false);
        update u;

        // Send notification to security team
        sendSecurityNotification('User frozen: ' + userId);
    }

    private static LoginHistory getLastLoginLocation(Id userId) {
        List<LoginHistory> history = [
            SELECT Id, CountryIso, LoginTime
            FROM LoginHistory
            WHERE UserId = :userId
            ORDER BY LoginTime DESC
            LIMIT 2
        ];

        return history.size() > 1 ? history[1] : null;
    }

    private static Double calculateDistance(String country1, String country2) {
        // Simplified distance calculation
        // Production code should use actual coordinates
        return country1 == country2 ? 0 : 5000;
    }

    private static Long calculateMinutes(DateTime time1, DateTime time2) {
        return (time2.getTime() - time1.getTime()) / (1000 * 60);
    }

    private static void sendImpossibleTravelAlert(Id userId, String username) {
        System.debug('Impossible travel detected for user: ' + username);
        // Send alert to security team
    }

    private static void sendSecurityNotification(String message) {
        // Implementation for security notifications
        System.debug('Security Alert: ' + message);
    }

    public class SecurityUtils {

    // Check object CRUD permissions
    public static Boolean hasObjectAccess(
        String objectName, 
        String operationType
    ) {
        Schema.SObjectType sObjType = Schema.getGlobalDescribe().get(objectName);
        if (sObjType == null) return false;

        Schema.DescribeSObjectResult describeResult = sObjType.getDescribe();

        switch on operationType.toLowerCase() {
            when 'create' {
                return describeResult.isCreateable();
            }
            when 'read' {
                return describeResult.isAccessible();
            }
            when 'update' {
                return describeResult.isUpdateable();
            }
            when 'delete' {
                return describeResult.isDeletable();
            }
            when else {
                return false;
            }
        }
    }

    // Check field-level security
    public static Boolean hasFieldAccess(
        String objectName,
        String fieldName,
        String accessType
    ) {
        Schema.SObjectType sObjType = Schema.getGlobalDescribe().get(objectName);
        if (sObjType == null) return false;

        Map<String, Schema.SObjectField> fields = 
            sObjType.getDescribe().fields.getMap();

        if (!fields.containsKey(fieldName)) return false;

        Schema.DescribeFieldResult fieldDescribe = 
            fields.get(fieldName).getDescribe();

        switch on accessType.toLowerCase() {
            when 'read' {
                return fieldDescribe.isAccessible();
            }
            when 'create' {
                return fieldDescribe.isCreateable();
            }
            when 'update' {
                return fieldDescribe.isUpdateable();
            }
            when else {
                return false;
            }
        }
    }

    // Strip inaccessible fields from query results
    public static List<SObject> stripInaccessible(
        List<SObject> records,
        AccessType accessType
    ) {
        if (records == null || records.isEmpty()) {
            return records;
        }

        SObjectAccessDecision decision = Security.stripInaccessible(
            accessType,
            records
        );

        return decision.getRecords();
    }
}

    // For dynamic SOQL, use String.escapeSingleQuotes()
    public static List<SObject> dynamicSearch(
        String objectName,
        String fieldName,
        String searchTerm
    ) {
        // Validate object and field names (whitelist approach)
        if (!isValidObject(objectName) || !isValidField(objectName, fieldName)) {
            throw new SecurityException('Invalid object or field');
        }

        // Escape search term
        String safeTerm = String.escapeSingleQuotes(searchTerm);

        // Build query safely
        String query = 'SELECT Id, ' + fieldName + 
                      ' FROM ' + objectName +
                      ' WHERE ' + fieldName + ' LIKE \'%' + safeTerm + '%\'';

        return Database.query(query);
    }

    private static Boolean isValidObject(String objectName) {
        return Schema.getGlobalDescribe().containsKey(objectName);
    }

    private static Boolean isValidField(String objectName, String fieldName) {
        Schema.SObjectType sObjType = Schema.getGlobalDescribe().get(objectName);
        if (sObjType == null) return false;

        Map<String, Schema.SObjectField> fields = 
            sObjType.getDescribe().fields.getMap();
        return fields.containsKey(fieldName);
    }

    public class AccessReport {
        public Boolean hasObjectAccess;
        public Boolean hasFieldAccess;
        public Boolean hasRecordAccess;
        public String diagnosis;
        public List<String> issues = new List<String>();
    }

    public static AccessReport diagnoseAccess(
        Id userId,
        Id recordId,
        String operation
    ) {
        AccessReport report = new AccessReport();

        // Get record details
        SObject record = Database.query(
            'SELECT Id, OwnerId FROM ' + recordId.getSObjectType() + 
            ' WHERE Id = :recordId'
        );

        String objectName = String.valueOf(recordId.getSObjectType());

        // Check object access
        report.hasObjectAccess = checkObjectAccess(
            userId, 
            objectName, 
            operation
        );

        if (!report.hasObjectAccess) {
            report.issues.add('User lacks ' + operation + 
                            ' permission on ' + objectName);
        }

        // Check record access
        report.hasRecordAccess = checkRecordAccess(userId, recordId);

        if (!report.hasRecordAccess) {
            report.issues.add('User cannot access this specific record');
            analyzeRecordAccess(userId, record, report);
        }

        // Generate diagnosis
        report.diagnosis = generateDiagnosis(report);

        return report;
    }

    private static Boolean checkObjectAccess(
        Id userId,
        String objectName,
        String operation
    ) {
        // Get user's profile and permission sets
        User u = [
            SELECT Id, ProfileId 
            FROM User 
            WHERE Id = :userId
        ];

        // Check profile permissions
        String query = 'SELECT PermissionsCreate, PermissionsRead, ' +
                      'PermissionsEdit, PermissionsDelete ' +
                      'FROM ObjectPermissions ' +
                      'WHERE ParentId = :u.ProfileId ' +
                      'AND SObjectType = :objectName';

        List<ObjectPermissions> perms = Database.query(query);

        if (perms.isEmpty()) return false;

        ObjectPermissions perm = perms[0];

        switch on operation.toLowerCase() {
            when 'create' { return perm.PermissionsCreate; }
            when 'read' { return perm.PermissionsRead; }
            when 'edit' { return perm.PermissionsEdit; }
            when 'delete' { return perm.PermissionsDelete; }
            when else { return false; }
        }
    }

    private static Boolean checkRecordAccess(Id userId, Id recordId) {
        try {
            UserRecordAccess ura = [
                SELECT RecordId, HasReadAccess, HasEditAccess, HasDeleteAccess
                FROM UserRecordAccess
                WHERE UserId = :userId
                AND RecordId = :recordId
            ];

            return ura.HasReadAccess;
        } catch (QueryException e) {
            return false;
        }
    }

    private static void analyzeRecordAccess(
        Id userId,
        SObject record,
        AccessReport report
    ) {
        // Check if user owns record
        if (record.get('OwnerId') == userId) {
            report.issues.add('User owns record but still lacks access');
            report.issues.add('Check object-level permissions');
        } else {
            report.issues.add('User does not own record');

            // Check role hierarchy
            Boolean hasRoleAccess = checkRoleHierarchyAccess(
                userId, 
                (Id)record.get('OwnerId')
            );

            if (!hasRoleAccess) {
                report.issues.add('User is not above owner in role hierarchy');
            }

            // Check sharing rules
            report.issues.add('Check if sharing rules grant access');
        }
    }

    private static Boolean checkRoleHierarchyAccess(Id userId, Id ownerId) {
        User currentUser = [SELECT UserRoleId FROM User WHERE Id = :userId];
        User owner = [SELECT UserRoleId FROM User WHERE Id = :ownerId];

        if (currentUser.UserRoleId == null || owner.UserRoleId == null) {
            return false;
        }

        // Simplified - actual implementation would check hierarchy
        return currentUser.UserRoleId == owner.UserRoleId;
    }

    private static String generateDiagnosis(AccessReport report) {
        if (report.issues.isEmpty()) {
            return 'User has full access';
        }

        String diagnosis = 'Access Issues Found:\n';
        for (String issue : report.issues) {
            diagnosis += '- ' + issue + '\n';
        }

        return diagnosis;
    }

                   ExtendedStatus, ApexClass.Name
            FROM AsyncApexJob

            AND CreatedDate = LAST_N_DAYS:7
            ORDER BY CreatedDate DESC

    public class SharingRecalculationBatch implements Database.Batchable<sObject> {

    private String objectName;
    private String whereClause;

    public SharingRecalculationBatch(String objectName, String whereClause) {
        this.objectName = objectName;
        this.whereClause = whereClause;
    }

    public Database.QueryLocator start(Database.BatchableContext bc) {
        String query = 'SELECT Id, OwnerId FROM ' + objectName;
        if (String.isNotBlank(whereClause)) {
            query += ' WHERE ' + whereClause;
        }
        return Database.getQueryLocator(query);
    }

    public void execute(Database.BatchableContext bc, List<sObject> scope) {
        // Force sharing recalculation by updating records
        // (update with same values triggers recalculation)

        List<sObject> toUpdate = new List<sObject>();
        for (sObject record : scope) {
            sObject updateRecord = record.getSObjectType().newSObject(record.Id);
            toUpdate.add(updateRecord);
        }

        if (!toUpdate.isEmpty()) {
            Database.update(toUpdate, false);
        }
    }

    public void finish(Database.BatchableContext bc) {
        System.debug('Sharing recalculation batch complete');
    }
}

    public class LockErrorHandler {

    public static void handleRecordWithRetry(Id recordId) {
        Integer maxRetries = 3;
        Integer retryCount = 0;
        Boolean success = false;

        while (retryCount < maxRetries && !success) {
            try {
                // Attempt operation
                Account acc = new Account(Id = recordId, Name = 'Updated');
                update acc;
                success = true;

            } catch (DmlException e) {
                if (e.getMessage().contains('UNABLE_TO_LOCK_ROW')) {
                    retryCount++;

                    if (retryCount < maxRetries) {
                        // Wait before retry (simulated with sleep in tests)
                        System.debug('Lock error, retrying... Attempt ' + retryCount);
                    } else {
                        throw new LockException('Failed after ' + maxRetries + ' retries');
                    }
                } else {
                    throw e;
                }
            }
        }
    }

    public class LockException extends Exception {}

    Question 1 (Administrator):
An organization has a Private OWD on Opportunities. Sales Managers need to 
view all opportunities for their team. What should you configure?

A) Create a sharing rule
B) Change OWD to Public Read Only
C) Assign managers to roles above sales reps
D) Grant View All permission

Answer: C
Explanation: Role hierarchy automatically grants access to records owned by 
subordinates when OWD is Private or Public Read Only.

Question 2 (Developer):
What happens when you use "with sharing" in an Apex class?

A) All SOQL queries are automatically filtered by sharing rules
B) The class respects the user's record-level access
C) Field-level security is automatically enforced
D) Object-level permissions are checked

Answer: B
Explanation: "with sharing" enforces record-level access based on user's 
sharing rules. FLS and object permissions must be checked explicitly.

allows customer control over encryption keys.
