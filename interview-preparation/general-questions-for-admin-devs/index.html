    General Questions for Administrators & Developers¶

    Salesforce Fundamentals¶

    Q: What is Salesforce?¶

    A: Salesforce is a cloud-based Customer Relationship Management (CRM) platform that provides tools for sales, service, marketing, and more. It operates on a multi-tenant architecture where multiple customers share the same infrastructure while maintaining data separation and security.

    Q: Explain the Salesforce architecture.¶

    A: Salesforce uses a multi-tenant architecture with three main layers: - User Interface Layer: Lightning Experience, Salesforce Mobile, APIs - Business Logic Layer: Apex, workflows, validation rules, processes - Data Model Layer: Standard and custom objects, relationships, fields

    Q: What are the different Salesforce Clouds?¶

    A: - Sales Cloud: CRM for sales teams - Service Cloud: Customer service and support - Marketing Cloud: Marketing automation - Commerce Cloud: E-commerce platform - Experience Cloud: Portals and communities - Analytics Cloud (Tableau CRM): Business intelligence - Industry Clouds: Financial Services, Health, Manufacturing, etc.

    Objects & Data Model¶

    Q: What's the difference between Standard and Custom Objects?¶

    A: - Standard Objects: Pre-built by Salesforce (Account, Contact, Opportunity, Case, Lead) - Custom Objects: Created by users to store specific business data, end with __c

    Q: Explain relationship types in Salesforce.¶

    A: - Lookup: Loosely coupled, no cascade delete, independent records - Master-Detail: Tightly coupled, cascade delete, roll-up summaries, sharing inherited - Many-to-Many: Junction object with two master-detail relationships - External Lookup: Relates to external objects (Salesforce Connect) - Hierarchical: User and Account objects only, self-referencing

    Q: What's the difference between a formula field and a roll-up summary field?¶

    A: - Formula Field: Calculated field using other fields, real-time, read-only, available on any object - Roll-up Summary: Aggregates child records (SUM, COUNT, MIN, MAX), only on master in master-detail, stored value

    Security¶

    Q: Explain Salesforce's security model layers.¶

    A: 1. Object-Level: Profile and permission sets control CRUD 2. Field-Level: FLS restricts field visibility/editability 3. Record-Level: OWD, role hierarchy, sharing rules, manual sharing

    Q: What are Organization-Wide Defaults (OWD)?¶

    A: OWD defines the baseline record access: - Private - Public Read Only - Public Read/Write - Controlled by Parent (master-detail) - Public Read/Write/Transfer (Leads, Cases, Campaigns)

    Q: Difference between Profile and Permission Set?¶

    A: - Profile: One per user, defines baseline permissions and access - Permission Set: Extends profile, grants additional permissions, multiple per user - Permission Set Group: Bundle of permission sets

    Automation¶

    Q: What automation tools are available in Salesforce?¶

    A: - Flow: Most powerful, screen and auto-launched flows - Process Builder: Being replaced by Flow - Workflow Rules: Legacy, simple field updates and email alerts - Approval Processes: Multi-step approval workflows - Triggers (Apex): For complex logic requiring code

    Q: When would you use a Flow vs. Apex Trigger?¶

    A: - Use Flow when: No code solution works, admins can maintain, standard functionality - Use Apex when: Complex business logic, external integration, performance-critical, advanced error handling

    Q: What are validation rules?¶

    A: Formulas that check data quality before saving a record. They prevent bad data entry by showing error messages when criteria aren't met.

    Reports & Dashboards¶

    Q: What report types are available?¶

    A: - Tabular: Simple list, no grouping, fastest - Summary: Grouped data with subtotals - Matrix: Grouped by rows and columns - Joined: Multiple report types together (up to 5 blocks)

    Q: What's the difference between a report and a dashboard?¶

    A: - Report: Detailed data view, exportable, up to 2000 rows displayed - Dashboard: Visual representation of reports, up to 20 components, refresh-able

    Data Management¶

    Q: What tools are available for data import/export?¶

    A: - Data Import Wizard: Up to 50,000 records, GUI-based, limited objects - Data Loader: Bulk operations, 5M records, command-line capable, all objects - Bulk API: Programmatic, large volumes, asynchronous - Weekly/Monthly Export: Scheduled full data export

    Q: How do you handle duplicate records?¶

    A: - Matching Rules: Define how duplicates are identified - Duplicate Rules: Actions when duplicates found (alert, block, allow) - Standard: Account, Contact, Lead - Custom: For custom objects

    Governor Limits¶

    Q: What are Governor Limits?¶

    A: Salesforce enforces limits to ensure multi-tenant resource sharing: - SOQL queries: 100 (sync), 200 (async) - DML statements: 150 - Heap size: 6MB (sync), 12MB (async) - CPU time: 10s (sync), 60s (async)

    Q: How do you avoid hitting governor limits?¶

    A: - Bulkify code (handle collections, not single records) - Avoid SOQL/DML in loops - Use async processing for large operations - Optimize queries with selective filters - Use @future or batch apex for long-running processes

    Development Basics¶

    Q: What is Apex?¶

    A: Salesforce's proprietary programming language, similar to Java. Object-oriented, strongly-typed, used for custom business logic, triggers, web services, and batch processing.

    Q: What is a trigger?¶

    A: Apex code that executes before or after DML operations (insert, update, delete, undelete). Used for complex automation beyond declarative tools.

    Q: What are trigger context variables?¶

    A: - Trigger.new: List of new records - Trigger.old: List of old records - Trigger.newMap: Map of new records - Trigger.oldMap: Map of old records - Trigger.isBefore/isAfter: Timing - Trigger.isInsert/isUpdate/isDelete/isUndelete: Operation type

    Q: What is SOQL?¶

    A: Salesforce Object Query Language, similar to SQL but for Salesforce. Used to query records from Salesforce objects.

    1
    SELECT Id, Name, Email FROM Contact WHERE Account.Name = 'Acme'

    Q: Difference between SOQL and SOSL?¶

    A: - SOQL: Query one object at a time, relationship queries, returns specific fields - SOSL: Search across multiple objects, text search, returns entire records

    Testing¶

    Q: What's the code coverage requirement?¶

    A: 75% for production deployment, but quality matters more than quantity. Each trigger must have some coverage.

    Q: What is Test.startTest() and Test.stopTest()?¶

    A: - Resets governor limits - Creates a new execution context - Useful for testing async processes - Code between them gets fresh limits

    Best Practices¶

    Q: What are Salesforce best practices you follow?¶

    A: - One trigger per object - Bulkify all code - Use descriptive naming - Comment complex logic - Follow org-wide standards - Comprehensive error handling - Thorough testing - Proper security (with sharing) - Avoid hard-coded IDs - Keep business logic out of triggers

    Q: How do you stay current with Salesforce?¶

    A: - Trailhead modules - Release notes (3 releases/year) - Salesforce blogs and videos - Community groups and events - Hands-on practice - Certifications - Salesforce podcasts

    Scenario Questions¶

    Q: How would you prevent users from deleting high-value opportunities?¶

    A: 1. Validation rule checking Amount > threshold AND NOT($Profile.Name = 'System Administrator') 2. Or use a before delete trigger to check criteria and prevent deletion 3. Or remove Delete permission from profiles/permission sets

    Q: Users are complaining about slow reports. How do you troubleshoot?¶

    A: 1. Check report filters - are they selective? 2. Review number of records being queried 3. Check for formula fields in criteria 4. Consider indexed fields 5. Review dashboard refresh frequency 6. Check system performance during run time 7. Optimize report type

    Q: How do you migrate customizations between orgs?¶

    A: - Change Sets (for related metadata) - ANT Migration Tool (for larger deployments) - Salesforce CLI (modern approach) - Unlocked Packages (for modular deployment) - Third-party tools (Copado, Gearset)
