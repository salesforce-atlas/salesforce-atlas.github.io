    Q: What is Salesforce's multi-tenant architecture and how does it impact development?¶

    A: Salesforce uses a multi-tenant architecture where multiple customers (tenants) share the same infrastructure, application code, and database while maintaining complete data isolation and security.

    Key Architectural Components:

    • Application Layer: Shared codebase serving all customers
    • Metadata Layer: Custom configurations unique to each org
    • Data Layer: Logically separated data for each tenant
    • Trust Layer: Security, authentication, and authorization

    Impact on Development:

    • Governor Limits: Enforced to prevent resource monopolization
    • No Direct Database Access: Use SOQL/SOSL instead of SQL
    • Metadata-Driven: Customizations via metadata, not core code changes
    • Automatic Upgrades: Three releases per year affect all orgs

    Governor Limits Context:

    ⚠️ SOQL Queries: 100 per transaction (synchronous)

    ⚠️ DML Statements: 150 per transaction

    ⚠️ Heap Size: 6 MB (synchronous), 12 MB (asynchronous)

    ⚠️ CPU Time: 10,000 ms (synchronous), 60,000 ms (asynchronous)

    Salesforce Edition Availability:

    • ✅ All editions run on multi-tenant architecture
    • ✅ Performance and limits consistent across editions
    • ✅ Sandbox environments mirror production architecture

    Best Practices:

    ✅ Design for bulk operations from the start

    ✅ Monitor governor limits during development

    ✅ Use asynchronous processing for large data volumes

    ✅ Implement proper exception handling

    Q: What is the difference between Standard Objects, Custom Objects, and External Objects?¶

    A: Salesforce provides different object types to handle various data storage needs, from pre-built entities to custom business requirements and external system integration.

    Standard Objects:

    • Definition: Pre-built objects provided by Salesforce
    • Examples: Account, Contact, Opportunity, Lead, Case
    • Characteristics: Cannot be deleted, have standard fields and functionality
    • Customization: Can add custom fields, relationships, and business logic

    Custom Objects:

    • Definition: User-created objects specific to business needs
    • Naming: End with __c suffix (e.g., Property__c)
    • Characteristics: Full control over fields, relationships, and security
    • Limits: Maximum 2,000 custom objects per org (Enterprise Edition and above)

    External Objects:

    • Definition: Objects that map to data stored outside Salesforce
    • Technology: Uses Salesforce Connect (formerly Lightning Connect)
    • Naming: End with __x suffix (e.g., ExternalInventory__x)
    • Use Cases: Real-time access to external data without replication

    Q: What is Salesforce's Order of Execution and why is it critical?¶

    A: The Order of Execution is the sequence in which Salesforce executes automation, validation, and database operations when a record is saved. Understanding this order is critical for preventing conflicts and ensuring predictable behavior.

    Complete Order of Execution:

    1. Load: Original record from database or initialize new record
    2. New Values: Overwrite with user-submitted values
    3. System Validation: Required fields, field formats, max length
    4. Before Triggers: Execute before save triggers
    5. Custom Validation Rules: User-defined validation logic
    6. Duplicate Rules: Check for duplicate records
    7. Save (Not Committed): Record saved to database but not committed
    8. After Triggers: Execute after save triggers
    9. Assignment Rules: Execute assignment rules (Leads, Cases)
    10. Auto-Response Rules: Send auto-response emails
    11. Workflow Rules: Execute workflow field updates
    12. Processes: Execute Process Builder processes
    13. Flows: Execute record-triggered flows
    14. Escalation Rules: Execute escalation rules (Cases)
    15. Roll-Up Summary Fields: Calculate roll-up summaries
    16. Criteria-Based Sharing: Recalculate sharing
    17. Commit: Commit all DML operations
    18. Post-Commit Logic: Execute after commit (async operations)

    Critical Understanding for Each Role:

    For Developers:

    • Before triggers fire before validation rules
    • After triggers see the committed data
    • Avoid recursive triggers by checking Trigger.isExecuting
    • Use trigger frameworks to control execution order

    For Administrators:

    • Validation rules run after before triggers
    • Workflow field updates trigger another save operation
    • Process Builder and Flows run after workflows
    • Multiple automations can cause recursion

    For Architects:

    • Design systems aware of multiple automation layers
    • Consider performance impact of cascading updates
    • Plan for governor limits in complex automation chains
    • Document execution flow for maintenance

        }
    }

    if (!tasksToCreate.isEmpty()) {
        insert tasksToCreate;
    }
}

    Q: What is the difference between Profiles and Permission Sets?¶

    A: Profiles and Permission Sets both control user access, but they serve different purposes in Salesforce's security model. Understanding when to use each is essential for scalable user management.

    Profiles:

    • Assignment: Every user must have exactly one profile
    • Purpose: Define baseline permissions and settings
    • Control: Object permissions, field permissions, app access, administrative permissions
    • Limitation: Cannot be additive (one per user)
    • Best Use: Define minimum access requirements by job role

    Permission Sets:

    • Assignment: Users can have multiple permission sets (0 to many)
    • Purpose: Grant additional permissions beyond profile
    • Control: Same permissions as profiles (additive only)
    • Benefit: More flexible than creating multiple profiles
    • Best Use: Grant temporary or role-specific access

    Permission Set Groups (Winter '20+):

    • Purpose: Bundle multiple permission sets together
    • Assignment: Simplify permission management at scale
    • Muting: Ability to mute specific permissions within the group

        Schema.SObjectType objType = Schema.getGlobalDescribe().get(objectName);

        Map<String, Schema.SObjectField> fields = objDescribe.fields.getMap();
        Schema.DescribeFieldResult fieldDescribe = fields.get(fieldName).getDescribe();

        return fieldDescribe.isAccessible();
    }
}

    Q: When should I use Flow versus Apex for automation?¶

    A: Choosing between Flow (declarative) and Apex (programmatic) depends on complexity, maintainability, and specific requirements. Modern Salesforce development emphasizes "clicks before code."

    Use Flow When:

    • Simple to Moderate Logic: Standard automation patterns
    • No Code Required: Admins can maintain without developers
    • Screen Flows: Guided user interactions needed
    • Declarative Best Practices: Salesforce recommends Flow first
    • Rapid Development: Faster to build and deploy
    • Record-Triggered Actions: Before/after save logic
    • Schedule-Based Automation: Time-based processes

    Use Apex When:

    • Complex Business Logic: Advanced algorithms or calculations
    • Bulk Processing: Large data volumes (10,000+ records)
    • Governor Limit Optimization: Need fine-grained control
    • External Integration: Complex API calls with error handling
    • Dynamic SOQL: Query logic determined at runtime
    • Recursion Control: Complex trigger patterns
    • Performance Critical: CPU-intensive operations
    • Third-Party Libraries: Need to use external code

    Flow Capabilities & Limitations:

    Capabilities:

    • Record-triggered flows (before/after save)
    • Screen flows for user input
    • Autolaunched flows for background processing
    • Scheduled flows for time-based automation
    • Platform Events integration
    • Apex Actions can be called from Flow
    • Subflows for reusability

    Limitations:

    ⚠️ SOQL Queries: 100 per flow interview (same as Apex)

    ⚠️ DML Statements: 150 per flow interview

    ⚠️ CPU Time: 10 seconds (same as Apex)

    ⚠️ Bulkification: Automatic but less control than Apex

    ⚠️ Complex Logic: Can become hard to maintain

    ⚠️ Debugging: More difficult than Apex debug logs

public class OpportunityTriggerHandler {

    public static void updateAccountRatings(
        List<Opportunity> newOpps, 
        Map<Id, Opportunity> oldMap
    ) {
        // Collect Account IDs
        Set<Id> accountIds = new Set<Id>();
        for (Opportunity opp : newOpps) {
            if (opp.AccountId != null) {
                // Only process if amount changed or new opportunity
                if (oldMap == null || 
                    opp.Amount != oldMap.get(opp.Id).Amount) {
                    accountIds.add(opp.AccountId);
                }
            }
        }

        if (accountIds.isEmpty()) return;

        // Aggregate opportunity amounts by account
        Map<Id, Decimal> accountTotals = new Map<Id, Decimal>();
        for (AggregateResult ar : [
            SELECT AccountId, SUM(Amount) totalAmount
            FROM Opportunity
            WHERE AccountId IN :accountIds
            AND StageName != 'Closed Lost'
            GROUP BY AccountId
        ]) {
            accountTotals.put(
                (Id)ar.get('AccountId'), 
                (Decimal)ar.get('totalAmount')
            );
        }

        // Update accounts
        List<Account> accountsToUpdate = new List<Account>();
        for (Id accId : accountIds) {
            Decimal total = accountTotals.get(accId);
            if (total != null) {
                Account acc = new Account(Id = accId);
                if (total > 1000000) {
                    acc.Rating = 'Hot';
                } else if (total > 500000) {
                    acc.Rating = 'Warm';
                } else {
                    acc.Rating = 'Cold';
                }
                accountsToUpdate.add(acc);
            }
        }

        if (!accountsToUpdate.isEmpty()) {
            update accountsToUpdate;
        }
    }
}

    Q: What is the proper way to bulkify Apex code?¶

    A: Bulkification is the practice of writing Apex code that efficiently handles multiple records in a single transaction. This is essential for avoiding governor limits and ensuring optimal performance.

    Why Bulkification Matters:

    • Salesforce processes records in batches (up to 200 per transaction)
    • Triggers must handle multiple records efficiently
    • Governor limits apply per transaction, not per record
    • Poor bulkification leads to limit exceptions in production

    public static void createHighValueAccountTasks(
        List<Account> newAccounts,
        Map<Id, Account> oldAccountMap
    ) {
        // Step 1: Collect Account IDs that meet criteria
        Set<Id> highValueAccountIds = new Set<Id>();

        for (Account acc : newAccounts) {
            // Check if revenue threshold crossed
            Boolean isNew = (oldAccountMap == null);
            Boolean revenueCrossedThreshold = false;

            if (!isNew) {
                Account oldAcc = oldAccountMap.get(acc.Id);
                revenueCrossedThreshold = (
                    acc.AnnualRevenue >= 1000000 && 
                    (oldAcc.AnnualRevenue == null || oldAcc.AnnualRevenue < 1000000)
                );
            } else if (acc.AnnualRevenue >= 1000000) {
                revenueCrossedThreshold = true;
            }

            if (revenueCrossedThreshold) {
                highValueAccountIds.add(acc.Id);
            }
        }

        if (highValueAccountIds.isEmpty()) {
            return; // Early exit if no work to do
        }

        // Step 2: Query related data (if needed)
        Map<Id, Account> accountsWithContacts = new Map<Id, Account>(
            [SELECT Id, Name, OwnerId,
                    (SELECT Id, Name, Email FROM Contacts WHERE Email != null LIMIT 5)
             FROM Account 
             WHERE Id IN :highValueAccountIds]
        );

        // Step 3: Query existing tasks to avoid duplicates
        Set<Id> accountsWithExistingTasks = new Set<Id>();
        for (Task existingTask : [
            SELECT WhatId 
            FROM Task 
            WHERE WhatId IN :highValueAccountIds 
            AND Subject = 'Review high-value account'
            AND CreatedDate = TODAY
        ]) {
            accountsWithExistingTasks.add(existingTask.WhatId);
        }

        // Step 4: Build records to insert
        List<Task> tasksToInsert = new List<Task>();
        List<ContentVersion> documentsToCreate = new List<ContentVersion>();

        for (Id accountId : highValueAccountIds) {
            // Skip if task already exists
            if (accountsWithExistingTasks.contains(accountId)) {
                continue;
            }

            Account acc = accountsWithContacts.get(accountId);

            // Create task
            Task t = new Task(
                Subject = 'Review high-value account',
                WhatId = accountId,
                OwnerId = acc.OwnerId,
                ActivityDate = Date.today().addDays(1),
                Priority = 'High',
                Status = 'Not Started',
                Description = 'Account revenue crossed $1M threshold. Review and update strategy.'
            );
            tasksToInsert.add(t);
        }

        // Step 5: Perform DML operations
        if (!tasksToInsert.isEmpty()) {
            insert tasksToInsert;
        }

        // Step 6: Handle errors gracefully
        if (!documentsToCreate.isEmpty()) {
            Database.SaveResult[] results = Database.insert(documentsToCreate, false);

            for (Integer i = 0; i < results.size(); i++) {
                if (!results[i].isSuccess()) {
                    System.debug('Error creating document: ' + results[i].getErrors());
                    // Log error to custom object or send email notification
                }
            }
        }
    }

    public static Map<Id, Contact> getContactsByAccountId(Set<Id> accountIds) {
        Map<Id, List<Contact>> contactsByAccount = new Map<Id, List<Contact>>();

        for (Contact con : [
            SELECT Id, FirstName, LastName, Email, AccountId
            FROM Contact
            WHERE AccountId IN :accountIds
        ]) {
            if (!contactsByAccount.containsKey(con.AccountId)) {
                contactsByAccount.put(con.AccountId, new List<Contact>());
            }
            contactsByAccount.get(con.AccountId).add(con);
        }

            FROM Opportunity
            WHERE AccountId IN :accountIds
            AND StageName != 'Closed Lost'
            GROUP BY AccountId
        ]) {
            totals.put(
                (Id)ar.get('AccountId'),
                (Decimal)ar.get('totalAmount')
            );
        }

        return totals;
    }

    public virtual class TriggerHandler {

    // Static map to prevent recursion
    private static Map<String, LoopCount> loopCountMap;
    private static Set<String> bypassedHandlers;

    static {
        loopCountMap = new Map<String, LoopCount>();
        bypassedHandlers = new Set<String>();
    }

    // Constructor
    public TriggerHandler() {
        this.setMaxLoopCount(5); // Default max iterations
    }

    // Main execution method
    public void run() {

        // Check if handler is bypassed
        if (bypassedHandlers.contains(getHandlerName())) {
            return;
        }

        // Check for recursive calls
        if (!validateRun()) {
            return;
        }

        addToLoopCount();

        // Route to appropriate method based on context
        if (Trigger.isBefore) {
            if (Trigger.isInsert) {
                this.beforeInsert();
            } else if (Trigger.isUpdate) {
                this.beforeUpdate();
            } else if (Trigger.isDelete) {
                this.beforeDelete();
            }
        } else if (Trigger.isAfter) {
            if (Trigger.isInsert) {
                this.afterInsert();
            } else if (Trigger.isUpdate) {
                this.afterUpdate();
            } else if (Trigger.isDelete) {
                this.afterDelete();
            } else if (Trigger.isUndelete) {
                this.afterUndelete();
            }
        }
    }

    // Virtual methods to be overridden
    protected virtual void beforeInsert() {}
    protected virtual void beforeUpdate() {}
    protected virtual void beforeDelete() {}
    protected virtual void afterInsert() {}
    protected virtual void afterUpdate() {}
    protected virtual void afterDelete() {}
    protected virtual void afterUndelete() {}

    // Recursion prevention
    private Boolean validateRun() {
        if (!loopCountMap.containsKey(getHandlerName())) {
            loopCountMap.put(getHandlerName(), new LoopCount());
        }

        LoopCount lc = loopCountMap.get(getHandlerName());

        if (lc.max < 0) return true;

        if (lc.count >= lc.max) {
            String errorMessage = 'Maximum loop count of ' + 
                String.valueOf(lc.max) + ' reached in ' + getHandlerName();
            throw new TriggerHandlerException(errorMessage);
        }

        return true;
    }

    private void addToLoopCount() {
        loopCountMap.get(getHandlerName()).increment();
    }

    public void setMaxLoopCount(Integer max) {
        if (!loopCountMap.containsKey(getHandlerName())) {
            loopCountMap.put(getHandlerName(), new LoopCount(max));
        } else {
            loopCountMap.get(getHandlerName()).max = max;
        }
    }

    public void clearMaxLoopCount() {
        this.setMaxLoopCount(-1);
    }

    public static void bypass(String handlerName) {
        bypassedHandlers.add(handlerName);
    }

    public static void clearBypass(String handlerName) {
        bypassedHandlers.remove(handlerName);
    }

    public static void clearAllBypasses() {
        bypassedHandlers.clear();
    }

    private String getHandlerName() {
        return String.valueOf(this).substring(0, String.valueOf(this).indexOf(':'));
    }

    // Inner class for loop counting
    private class LoopCount {
        private Integer max;
        private Integer count;

        public LoopCount() {
            this(5);
        }

        public LoopCount(Integer max) {
            this.max = max;
            this.count = 0;
        }

        public void increment() {
            this.count++;
        }
    }

    public class TriggerHandlerException extends Exception {}
}

    public class AccountTriggerHelper {

    // Before Insert Logic
    public static void setDefaultValues(List<Account> accounts) {
        for (Account acc : accounts) {
            if (String.isBlank(acc.Industry)) {
                acc.Industry = 'Other';
            }
            if (String.isBlank(acc.Type)) {
                acc.Type = 'Prospect';
            }
        }
    }

    public static void validateIndustry(List<Account> accounts) {
        Set<String> validIndustries = new Set<String>{
            'Technology', 'Healthcare', 'Finance', 'Manufacturing', 'Retail', 'Other'
        };

        for (Account acc : accounts) {
            if (!validIndustries.contains(acc.Industry)) {
                acc.Industry.addError('Please select a valid industry');
            }
        }
    }

    // Before Update Logic
    public static void preventRatingDecrease(
        List<Account> newAccounts, 
        Map<Id, Account> oldAccountMap
    ) {
        for (Account acc : newAccounts) {
            Account oldAcc = oldAccountMap.get(acc.Id);

            if (oldAcc.Rating == 'Hot' && acc.Rating != 'Hot') {
                acc.Rating.addError('Cannot decrease rating from Hot. Please contact manager.');
            }
        }

    public static void updateModifiedFields(
        List<Account> newAccounts,
        Map<Id, Account> oldAccountMap
    ) {
        for (Account acc : newAccounts) {
            Account oldAcc = oldAccountMap.get(acc.Id);

            // Track significant changes
            if (acc.AnnualRevenue != oldAcc.AnnualRevenue ||
                acc.Industry != oldAcc.Industry) {
                acc.Last_Significant_Change__c = System.now();
            }
        }
    }

    // After Insert Logic
    public static void createWelcomeTask(List<Account> accounts) {
        List<Task> tasksToInsert = new List<Task>();

        for (Account acc : accounts) {
            Task t = new Task(
                Subject = 'Welcome new account: ' + acc.Name,
                WhatId = acc.Id,
                OwnerId = acc.OwnerId,

    public static void sendNotificationToOwner(List<Account> accounts) {
        Set<Id> ownerIds = new Set<Id>();
        for (Account acc : accounts) {
            ownerIds.add(acc.OwnerId);
        }

        Map<Id, User> owners = new Map<Id, User>(
            [SELECT Id, Email FROM User WHERE Id IN :ownerIds]
        );

        List<Messaging.SingleEmailMessage> emails = new List<Messaging.SingleEmailMessage>();

        for (Account acc : accounts) {
            User owner = owners.get(acc.OwnerId);
            if (owner != null && owner.Email != null) {
                Messaging.SingleEmailMessage email = new Messaging.SingleEmailMessage();
                email.setToAddresses(new List<String>{ owner.Email });
                email.setSubject('New Account Assigned: ' + acc.Name);
                email.setPlainTextBody(
                    'A new account has been assigned to you:\n\n' +
                    'Account Name: ' + acc.Name + '\n' +
                    'Industry: ' + acc.Industry + '\n\n' +
                    'Please review and take appropriate action.'
                );
                emails.add(email);
            }
        }

        if (!emails.isEmpty()) {
            Messaging.sendEmail(emails);
        }
    }

    // After Update Logic
    public static void updateRelatedContacts(
        List<Account> newAccounts,
        Map<Id, Account> oldAccountMap
    ) {
        Set<Id> accountsWithBillingChanges = new Set<Id>();

        for (Account acc : newAccounts) {
            Account oldAcc = oldAccountMap.get(acc.Id);

            if (acc.BillingCity != oldAcc.BillingCity ||
                acc.BillingState != oldAcc.BillingState) {
                accountsWithBillingChanges.add(acc.Id);
            }
        }

        if (accountsWithBillingChanges.isEmpty()) return;

        List<Contact> contactsToUpdate = [
            SELECT Id, AccountId, MailingCity, MailingState
            FROM Contact
            WHERE AccountId IN :accountsWithBillingChanges
            AND Sync_Address_With_Account__c = true
        ];

        Map<Id, Account> accountMap = new Map<Id, Account>(
            [SELECT Id, BillingCity, BillingState 
             FROM Account 
             WHERE Id IN :accountsWithBillingChanges]
        );

        for (Contact con : contactsToUpdate) {
            Account acc = accountMap.get(con.AccountId);
            con.MailingCity = acc.BillingCity;
            con.MailingState = acc.BillingState;
        }

        if (!contactsToUpdate.isEmpty()) {
            update contactsToUpdate;
        }
    }

    public static void logSignificantChanges(
        List<Account> newAccounts,
        Map<Id, Account> oldAccountMap

                    Field_Changed__c = 'AnnualRevenue',
                    Old_Value__c = String.valueOf(oldAcc.AnnualRevenue),
                    New_Value__c = String.valueOf(acc.AnnualRevenue),
                    Changed_By__c = UserInfo.getUserId(),
                    Change_Date__c = System.now()

            }
        }

        }
    }

                Account_Name__c = acc.Name,
                Industry__c = acc.Industry,
                Annual_Revenue__c = acc.AnnualRevenue,
                Deleted_Date__c = System.now(),
                Deleted_By__c = UserInfo.getUserId()
            ));
        }

        if (!archiveRecords.isEmpty()) {
            insert archiveRecords;
        }

import { NavigationMixin } from 'lightning/navigation';
import searchAccounts from '@salesforce/apex/AccountController.searchAccounts';
import { ShowToastEvent } from 'lightning/platformShowToastEvent';

export default class AccountSearch extends NavigationMixin(LightningElement) {
    @track searchTerm = '';
    @track accounts = [];
    @track error;
    @track isLoading = false;

    // Debounce timeout
    searchTimeout;

    // Getter for checking if accounts exist
    get hasAccounts() {
        return this.accounts && this.accounts.length > 0;
    }

    handleSearchChange(event) {
        // Clear previous timeout
        clearTimeout(this.searchTimeout);

        this.searchTerm = event.target.value;

        // Debounce search (wait 300ms after user stops typing)
        this.searchTimeout = setTimeout(() => {
            this.performSearch();
        }, 300);
    }

    async performSearch() {
        if (!this.searchTerm || this.searchTerm.length < 2) {
            this.accounts = [];
            return;
        }

        this.isLoading = true;
        this.error = undefined;

        try {
            const results = await searchAccounts({ 
                searchTerm: this.searchTerm 
            });
            this.accounts = results;
        } catch (error) {
            this.error = error.body?.message || 'An error occurred while searching';
            this.accounts = [];

            // Show toast notification
            this.dispatchEvent(
                new ShowToastEvent({
                    title: 'Error',
                    message: this.error,
                    variant: 'error'
                })
            );
        } finally {
            this.isLoading = false;
        }
    }

    handleAccountClick(event) {
        const accountId = event.currentTarget.dataset.id;

        // Navigate to account record page
        this[NavigationMixin.Navigate]({
            type: 'standard__recordPage',
            attributes: {
                recordId: accountId,
                objectApiName: 'Account',
                actionName: 'view'
            }
        });
    }
}

    Q: What are the different Salesforce integration patterns and when should each be used?¶

    A: Salesforce provides multiple integration patterns to connect with external systems. Choosing the right pattern depends on data volume, latency requirements, and system capabilities.

    Integration Pattern Overview:

    1. Request-Response (Synchronous):

    • Use Case: Real-time data needs, user-initiated actions
    • Technology: REST API, SOAP API
    • Direction: Bidirectional
    • Example: Credit check during order placement
    • Latency: Low (sub-second to seconds)
    • Volume: Low to medium (hundreds to thousands per hour)

    2. Fire-and-Forget (Asynchronous):

    • Use Case: Non-critical updates, one-way data flow
    • Technology: Outbound Messages, Platform Events
    • Direction: Salesforce → External
    • Example: Send new lead to marketing automation
    • Latency: Medium (seconds to minutes)
    • Volume: Medium (thousands per hour)

    3. Batch Data Synchronization:

    • Use Case: Large volumes, scheduled updates
    • Technology: Bulk API, Data Loader, ETL tools
    • Direction: Bidirectional
    • Example: Nightly product catalog sync
    • Latency: High (hours)
    • Volume: High (millions of records)

    4. Remote Process Invocation:

    • Use Case: Complex processing offloaded to external system
    • Technology: REST/SOAP callouts, Named Credentials
    • Direction: Salesforce → External → Salesforce
    • Example: Tax calculation service
    • Latency: Low to medium
    • Volume: Low to medium

    5. UI Update Based on Data Changes:

    • Use Case: Real-time UI updates, notifications
    • Technology: Platform Events, Streaming API, Change Data Capture
    • Direction: Salesforce → External
    • Example: Live dashboard updates
    • Latency: Near real-time (< 1 second)
    • Volume: Medium to high

            List<Object> products = (List<Object>)JSON.deserializeUntyped(res.getBody());
            processBulkProducts(products);
        }
    }

    private static void processBulkProducts(List<Object> products) {
        List<Product2> productsToUpsert = new List<Product2>();
        Set<String> externalIds = new Set<String>();

        // Collect external IDs
        for (Object prodObj : products) {
            Map<String, Object> prod = (Map<String, Object>)prodObj;
            externalIds.add((String)prod.get('externalId'));
        }

        // Query existing products
        Map<String, Product2> existingProducts = new Map<String, Product2>();
        for (Product2 prod : [
            SELECT Id, External_ID__c, Name
            FROM Product2
            WHERE External_ID__c IN :externalIds
        ]) {
            existingProducts.put(prod.External_ID__c, prod);
        }

        // Prepare upsert
        for (Object prodObj : products) {
            Map<String, Object> prod = (Map<String, Object>)prodObj;
            String extId = (String)prod.get('externalId');

            Product2 p;
            if (existingProducts.containsKey(extId)) {
                p = existingProducts.get(extId);
            } else {
                p = new Product2();
            }

            p.Name = (String)prod.get('name');
            p.ProductCode = (String)prod.get('code');
            p.External_ID__c = extId;
            p.IsActive = true;

            productsToUpsert.add(p);
        }

        // Upsert in batches
        if (!productsToUpsert.isEmpty()) {
            Database.UpsertResult[] results = Database.upsert(
                productsToUpsert, 
                Product2.External_ID__c,
                false
            );

            // Log failures
            for (Integer i = 0; i < results.size(); i++) {
                if (!results[i].isSuccess()) {
                    System.debug('Failed to upsert product: ' + productsToUpsert[i].Name);
                    for (Database.Error error : results[i].getErrors()) {
                        System.debug('Error: ' + error.getMessage());
                    }
                }
            }
        }
    }

    Q: How does Salesforce's sharing model work?¶

    A: Salesforce's sharing model is a comprehensive security framework that controls record-level access through multiple layers. Understanding this model is critical for proper data security implementation.

    Sharing Model Layers (Most to Least Restrictive):

    1. Organization-Wide Defaults (OWD):

    • Definition: Baseline access level for all users
    • Options: Private, Public Read Only, Public Read/Write, Controlled by Parent
    • Scope: Applies organization-wide
    • Use: Sets the most restrictive access level

    2. Role Hierarchy:

    • Definition: Tree structure defining reporting relationships
    • Behavior: Users higher in hierarchy can access records owned by subordinates
    • Options: Can be disabled per object ("Grant Access Using Hierarchies")
    • Use: Reflects organizational structure

    3. Sharing Rules:

    • Definition: Automatic sharing based on criteria or ownership
    • Types: Owner-based, Criteria-based
    • Direction: Can only open up access (never restrict)
    • Use: Extend access beyond OWD and hierarchy

    4. Manual Sharing:

    • Definition: Record owner grants access to specific users/groups
    • Scope: Individual records
    • Use: Ad-hoc access needs

    5. Apex Managed Sharing:

    • Definition: Programmatic sharing using Apex
    • Control: Full control over share records
    • Use: Complex sharing logic not achievable declaratively

    public static void shareOpportunitiesByTerritory() {
        // Get territory assignments
        Map<Id, Set<Id>> territoryToUsers = new Map<Id, Set<Id>>();

        for (UserTerritory__c ut : [

            WHERE Active__c = true

            territoryToUsers.get(ut.Territory__c).add(ut.User__c);

        Map<Id, Set<Id>> oppToUsers = new Map<Id, Set<Id>>();

        for (Opportunity opp : [
            SELECT Id, Territory__c
            FROM Opportunity
            WHERE Territory__c IN :territoryToUsers.keySet()
            AND StageName != 'Closed Won'
            AND StageName != 'Closed Lost'
        ]) {
            oppToUsers.put(opp.Id, territoryToUsers.get(opp.Territory__c));

        List<OpportunityShare> sharesToCreate = new List<OpportunityShare>();

        for (Id oppId : oppToUsers.keySet()) {
            for (Id userId : oppToUsers.get(oppId)) {
                OpportunityShare share = new OpportunityShare();
                share.OpportunityId = oppId;
                share.UserOrGroupId = userId;
                share.OpportunityAccessLevel = 'Edit';
                share.RowCause = Schema.OpportunityShare.RowCause.Territory__c;

    public static List<Account> getAccountsWithDetails(Set<Id> accountIds) {

            ORDER BY Name
        ];
    }

    // Example 2: Aggregate Query with Grouping
    public static Map<String, Decimal> getRevenueBySector() {
        Map<String, Decimal> revenueMap = new Map<String, Decimal>();

        for (AggregateResult ar : [
            SELECT Industry, SUM(AnnualRevenue) totalRevenue, COUNT(Id) accountCount
            FROM Account
            WHERE AnnualRevenue != null
            AND CreatedDate = THIS_YEAR
            GROUP BY Industry
            HAVING SUM(AnnualRevenue) > 1000000
            ORDER BY SUM(AnnualRevenue) DESC
        ]) {
            String industry = (String)ar.get('Industry');
            Decimal revenue = (Decimal)ar.get('totalRevenue');
            revenueMap.put(industry, revenue);
        }

        return revenueMap;
    }

    public static List<Account> getAccountsWithOpenOpportunities() {
        return [
            SELECT Id, Name,
                   (SELECT Id, Name, StageName, Amount, Probability
                    FROM Opportunities
                    WHERE IsClosed = false
                    AND Amount > 50000
                    ORDER BY Amount DESC)
            FROM Account
            WHERE Id IN (

                AND Amount > 50000

    public class ExceptionHandlingExamples {

    // Comprehensive exception handling
    public static void robustExceptionHandling() {
        try {
            // Risky operation
            Account acc = [SELECT Id FROM Account WHERE Name = 'NonExistent'];
            update acc;

        } catch (QueryException e) {
            // Specific exception for query issues
            System.debug('Query error: ' + e.getMessage());
            System.debug('Line number: ' + e.getLineNumber());
            System.debug('Stack trace: ' + e.getStackTraceString());

        } catch (DmlException e) {
            // Specific exception for DML issues
            System.debug('DML error: ' + e.getMessage());
            System.debug('Number of errors: ' + e.getNumDml());

            for (Integer i = 0; i < e.getNumDml(); i++) {
                System.debug('Error ' + i + ': ' + e.getDmlMessage(i));
                System.debug('Failed record ID: ' + e.getDmlId(i));
                System.debug('Field causing error: ' + e.getDmlFieldNames(i));
            }

        } catch (Exception e) {
            // Generic exception catch-all
            System.debug('Unexpected error: ' + e.getMessage());
            System.debug('Type: ' + e.getTypeName());
            System.debug('Line: ' + e.getLineNumber());
            System.debug('Stack: ' + e.getStackTraceString());

        } finally {
            // Always executes
            System.debug('Cleanup code here');
        }
    }

    // Custom exception
    public class CustomBusinessException extends Exception {
        private String errorCode;

        public CustomBusinessException(String message, String code) {
            this(message);
            this.errorCode = code;
        }

        public String getErrorCode() {
            return this.errorCode;
        }
    }

    public static void throwCustomException() {
        throw new CustomBusinessException('Business rule violated', 'BUS001');
    }

    public static void partialSuccessPattern() {
        List<Account> accounts = new List<Account>{
            new Account(Name = 'Valid Account'),

        };

        // allOrNone = false allows partial success
        Database.SaveResult[] results = Database.insert(accounts, false);

                }
            }
        }
