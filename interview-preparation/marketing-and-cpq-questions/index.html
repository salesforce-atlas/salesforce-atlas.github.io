    Q: What is Salesforce CPQ and why is it important?¶

    A: Salesforce CPQ (Configure, Price, Quote) is a sales automation tool that helps sales teams quickly and accurately configure products, calculate pricing, and generate quotes for complex product offerings.

    Key Capabilities:

    • Product Configuration: Guided selling with product rules and dependencies
    • Dynamic Pricing: Automated price calculations based on rules, volume, and discounts
    • Quote Generation: Professional quote documents with custom templates
    • Approval Workflows: Automated approval processes for discounts and special terms
    • Revenue Recognition: Integration with Salesforce Billing for subscription management

    Core CPQ Objects:

    • Product2: Standard Salesforce product object
    • SBQQ__Product__c: CPQ-specific product with additional configuration fields
    • SBQQ__Quote__c: CPQ quote object
    • SBQQ__QuoteLine__c: Individual line items on a quote
    • SBQQ__PriceRule__c: Automated pricing rules
    • SBQQ__ProductRule__c: Product configuration rules

    Salesforce Edition Requirements:

    • ✅ Enterprise Edition (minimum)
    • ✅ Unlimited Edition
    • ✅ Performance Edition
    • ❌ Not available in Professional or Essentials

    Use Cases:

    • Complex product bundles with dependencies
    • Volume-based or tiered pricing models
    • Subscription and usage-based pricing
    • Multi-year contracts with renewals
    • Partner and channel pricing

    Q: What is Salesforce Marketing Cloud and how does it differ from Pardot?¶

    A: Marketing Cloud is Salesforce's enterprise marketing automation platform for B2C marketing, while Pardot (now Account Engagement) is designed for B2B marketing automation.

    Marketing Cloud:

    • Target Audience: B2C, large-scale consumer marketing
    • Primary Use: Email marketing, mobile messaging, social media advertising, web personalization
    • Data Model: Contact model (separate from Sales Cloud)
    • Complexity: Enterprise-level platform with multiple studios

    Key Marketing Cloud Studios:

    • Email Studio: Email campaign creation and management
    • Mobile Studio: SMS, push notifications, and mobile messaging
    • Social Studio: Social media listening and engagement
    • Advertising Studio: Targeted advertising on Facebook, Google, LinkedIn
    • Journey Builder: Customer journey orchestration
    • Data Studio: Data management and integration

    Pardot/Account Engagement:

    • Target Audience: B2B marketing and lead nurturing
    • Primary Use: Lead scoring, nurturing, ROI reporting
    • Data Model: Integrated with Salesforce CRM (Leads, Contacts, Accounts)
    • Complexity: More straightforward B2B focus

    Key Pardot Features:

    • Lead Scoring: Automatic lead qualification based on behavior
    • Lead Nurturing: Drip campaigns and automated engagement
    • Landing Pages: Custom landing page builder
    • Forms: Web form creation and tracking
    • ROI Reporting: Campaign attribution and revenue tracking

    Integration Differences:

    • Marketing Cloud requires Marketing Cloud Connect for CRM integration
    • Pardot has native Salesforce CRM integration
    • Marketing Cloud uses separate contact database
    • Pardot syncs directly with Leads and Contacts

    Salesforce Edition Requirements:

    • Marketing Cloud: Standalone product with various editions
    • Pardot: Available as add-on to Sales Cloud (Growth, Plus, Advanced editions)

    When to Use Each:

    • Marketing Cloud: High-volume consumer marketing, multi-channel campaigns, millions of contacts
    • Pardot: B2B lead generation, sales and marketing alignment, account-based marketing

    Q: What is the relationship between CPQ and Opportunity in Salesforce?¶

    A: CPQ Quotes are created from Opportunities and maintain a parent-child relationship where the Opportunity represents the overall sales deal and CPQ Quotes contain the detailed product configuration and pricing.

    Quote-Opportunity Relationship:

    • One-to-Many: One Opportunity can have multiple Quotes
    • Primary Quote: One Quote can be designated as the Primary Quote
    • Synced Quote: The Primary Quote syncs its products and amounts to the Opportunity
    • Quote Lines: Automatically create or update Opportunity Products when synced

    Workflow:

    • Create Opportunity in Sales Cloud
    • Click "New Quote" from Opportunity
    • Configure products in CPQ
    • Set Quote as Primary
    • Quote Line Items sync to Opportunity Products
    • Opportunity Amount updates from Quote

    Key Fields Synced:

    • Total Amount: Quote total syncs to Opportunity Amount
    • Products: Quote Lines sync to Opportunity Products
    • Close Date: Can sync from Quote to Opportunity
    • Status: Quote status affects Opportunity stage

    Q: What are the key objects in the CPQ data model?¶

    A: The CPQ data model consists of several custom objects that work together to enable product configuration, pricing, and quote generation.

    Core CPQ Objects:

    Quote Objects:

    • SBQQ__Quote__c: Master quote record containing customer, dates, and terms
    • SBQQ__QuoteLine__c: Individual products added to the quote
    • SBQQ__QuoteLineGroup__c: Grouping mechanism for quote lines

    Product Objects:

    • Product2: Standard Salesforce product (shared with Sales Cloud)
    • SBQQ__Product__c: CPQ-enhanced product with configuration options
    • SBQQ__ProductOption__c: Defines optional or required features
    • SBQQ__ProductFeature__c: Feature sets for product configuration

    Pricing Objects:

    • SBQQ__PriceRule__c: Automated pricing calculations
    • SBQQ__PriceCondition__c: Conditions that trigger price rules
    • SBQQ__PriceAction__c: Actions executed by price rules
    • SBQQ__DiscountSchedule__c: Volume-based discount tiers
    • SBQQ__PriceBook__c: Custom price books (extends standard PriceBook2)

    Configuration Objects:

    • SBQQ__ProductRule__c: Configuration rules and validations
    • SBQQ__ConfigurationAttribute__c: Dynamic product attributes
    • SBQQ__OptionConstraint__c: Dependencies between product options

    Contract & Subscription Objects:

    • Contract: Standard Salesforce contract
    • SBQQ__Subscription__c: Subscription records for recurring revenue
    • Asset: Standard asset records for installed products
    • SBQQ__ContractedPrice__c: Customer-specific contracted pricing

    Object Relationships:

    Key Relationships:

    • Quote → Quote Lines (Master-Detail)
    • Quote Line → Product (Lookup)
    • Quote → Opportunity (Lookup)
    • Product Option → Product (Lookup)
    • Price Rule → Price Conditions and Price Actions
    • Subscription → Quote Line (Lookup)

    Q: How do you set up a product bundle in Salesforce CPQ?¶

    A: Product bundles allow you to sell groups of products together with parent-child relationships and configuration options.

    Bundle Components:

    • Parent Product: The main product that customers select
    • Product Options: Child products that can be added to the bundle
    • Product Features: Logical groupings of options
    • Configuration Attributes: Dynamic fields for customization

    Setup Steps:

    Step 1: Create the Parent Product

    • Create Product2 record
    • Mark as "Component" = false
    • Set "Has Configuration Attributes" if needed
    • Define pricing model (one-time or subscription)

    Step 2: Create Child Products

    • Create Product2 records for each component
    • Mark as "Component" = true (optional)
    • Set individual pricing

    Step 3: Create Product Features (Optional)

    • Create SBQQ__ProductFeature__c records
    • Group related options together
    • Set feature type (Required, Optional)
    • Define min/max selections

    Step 4: Create Product Options

    • Create SBQQ__ProductOption__c records
    • Link to parent product (Configured SKU)
    • Link to child product (Optional SKU)
    • Set quantity behavior
    • Define if option is required

    Q: How do Product Rules work in Salesforce CPQ?¶

    A: Product Rules are automation tools that guide product configuration, validate selections, display alerts, and dynamically adjust products based on conditions.

    Product Rule Types:

    Validation Rules:

    • Enforce business logic during configuration
    • Prevent invalid product combinations
    • Display error messages to users
    • Block quote save until resolved

    Selection Rules:

    • Automatically add/remove products
    • Configure based on criteria
    • Streamline configuration process
    • Pre-select recommended options

    Alert Rules:

    • Display warning messages
    • Provide guidance without blocking
    • Inform users of considerations
    • Don't prevent quote save

    Filter Rules:

    • Control which products are visible
    • Simplify product selection
    • Reduce configuration complexity
    • Hide irrelevant options

    Product Rule Components:

    Configuration Rule (SBQQ__ProductRule__c):

    • Type: Validation, Selection, Alert, or Filter
    • Scope: Product or Quote
    • Evaluation Event: Edit, Save, Always, Load
    • Error Message: Displayed for Validation/Alert rules
    • Active: Enable/disable rule

    Error Conditions (SBQQ__ErrorCondition__c):

    • Define when rule triggers
    • Can be positive or negative logic
    • Support multiple conditions with AND/OR
    • Reference product fields or quote fields

    Configuration (SBQQ__Configuration__c):

    • Links condition to product rule
    • Defines which products rule applies to
    • Multiple configurations per rule

    Product Actions (SBQQ__ProductAction__c):

    • Add, remove, show, or hide products
    • Set quantities or field values
    • Execute when conditions are met

    Q: What are Configuration Attributes and how are they used?¶

    A: Configuration Attributes are custom fields that appear during product configuration, allowing dynamic customization of products and quote lines based on user input.

    Configuration Attribute Basics:

    • Custom fields that appear in the configurator
    • Capture additional information during configuration
    • Drive pricing, product selection, or quote behavior
    • Can be required or optional
    • Support various data types

    Configuration Attribute Types:

    Set Automatically:

    • Values calculated by formulas or rules
    • Not directly editable by users
    • Used for backend calculations

    Enter Manually:

    • User provides value during configuration
    • Most common type
    • Can be used in formulas and rules

    Hidden:

    • Not displayed to users
    • Used for calculations or rule logic
    • Set by automation

    Q: How does pricing hierarchy work in Salesforce CPQ?¶

    A: CPQ uses a multi-tier pricing hierarchy that determines the final price for quote line items, starting from list price and applying various pricing methods in sequence.

    Pricing Hierarchy (in order):

    List Price:

    • Base price from Price Book
    • Starting point for all calculations
    • Can vary by price book and currency

    Cost:

    • Product cost (if tracked)
    • Used for margin calculations
    • Optional field

    Customer Price:

    • Special pricing for specific customers
    • Stored in Contracted Price object
    • Overrides list price

    Partner Price:

    • Pricing for partner/channel deals
    • Partner-specific discounts
    • Distribution channel pricing

    Price Rules:

    • Automated pricing calculations
    • Volume discounts, promotions, bundles
    • Most flexible pricing method

    Discount Schedule:

    • Tiered discount based on quantity
    • Automatic application
    • Volume-based pricing

    Manual Discount:

    • Sales rep applies discount
    • Can be percentage or amount
    • Subject to approval workflows

    Final Net Price:

    • Calculated after all adjustments
    • What customer actually pays
    • Shown on quote and proposal

    Q: How do you create and configure Price Rules in Salesforce CPQ?¶

    A: Price Rules automate pricing calculations by evaluating conditions and executing actions to adjust prices, add products, or update fields on quote lines.

    Price Rule Components:

    SBQQ__PriceRule__c (Main Rule):

    • Name: Descriptive rule name
    • Active: Enable/disable rule
    • Evaluation Order: Sequence of execution (lower runs first)
    • Evaluation Scope: Calculator or Configurator
    • Conditions Met: All or Any conditions must be true
    • Calculator Evaluation Event: Before Calculate, On Calculate
    • Configurator Evaluation Event: Before Load, On Load, Edit, Save

    SBQQ__PriceCondition__c (When):

    • Defines when rule should fire
    • Tests field values on Quote, Quote Line, or related objects
    • Multiple conditions linked by AND/OR logic
    • Supports standard operators (equals, greater than, etc.)

    SBQQ__PriceAction__c (Then):

    • Defines what happens when conditions are met
    • Can update prices, set fields, or perform calculations
    • Uses formulas for complex calculations
    • Multiple actions can execute per rule

public class PriceRuleEngine {

    public void evaluatePriceRules(SBQQ__Quote__c quote) {
        // Get active price rules in evaluation order
        List<SBQQ__PriceRule__c> rules = [
            SELECT Id, Name, SBQQ__EvaluationOrder__c,
                   (SELECT Id, SBQQ__Field__c, SBQQ__Operator__c, 
                           SBQQ__Value__c 
                    FROM SBQQ__PriceConditions__r),
                   (SELECT Id, SBQQ__Field__c, SBQQ__Formula__c,
                           SBQQ__ValueField__c
                    FROM SBQQ__PriceActions__r)
            FROM SBQQ__PriceRule__c
            WHERE SBQQ__Active__c = true
            ORDER BY SBQQ__EvaluationOrder__c
        ];

        for (SBQQ__PriceRule__c rule : rules) {
            if (evaluateConditions(rule, quote)) {
                executeActions(rule, quote);
            }
        }
    }

    private Boolean evaluateConditions(
        SBQQ__PriceRule__c rule, 
        SBQQ__Quote__c quote
    ) {
        // Evaluate each condition
        for (SBQQ__PriceCondition__c condition : 
             rule.SBQQ__PriceConditions__r) {
            // Check condition logic
            Boolean conditionMet = checkCondition(condition, quote);
            if (!conditionMet && rule.SBQQ__ConditionsMet__c == 'All') {
                return false; // All conditions required
            }
        }
        return true;
    }

    private void executeActions(
        SBQQ__PriceRule__c rule,
        SBQQ__Quote__c quote
    ) {
        // Execute each action
        for (SBQQ__PriceAction__c action : 
             rule.SBQQ__PriceActions__r) {
            applyPriceAction(action, quote);
        }
    }
}

public class QuoteDocumentGenerator {

    public static Id generateQuoteDocument(Id quoteId) {
        // Get quote with template
        SBQQ__Quote__c quote = [
            SELECT Id, SBQQ__QuoteTemplate__c
            FROM SBQQ__Quote__c
            WHERE Id = :quoteId
        ];

        // Generate PDF using CPQ API
        PageReference quotePdf = Page.SBQQ__Quote;
        quotePdf.getParameters().put('id', quoteId);

        Blob pdfContent;
        if (Test.isRunningTest()) {
            pdfContent = Blob.valueOf('Test PDF Content');
        } else {
            pdfContent = quotePdf.getContent();
        }

        // Create attachment
        Attachment att = new Attachment(
            Name = 'Quote_' + quote.Id + '.pdf',
            ParentId = quoteId,
            Body = pdfContent,
            ContentType = 'application/pdf'
        );
        insert att;

        return att.Id;
    }

    // Email quote document
    public static void emailQuoteDocument(Id quoteId, String toEmail) {
        Id attachmentId = generateQuoteDocument(quoteId);

        Messaging.EmailFileAttachment attachment = 
            new Messaging.EmailFileAttachment();
        attachment.setFileName('Quote.pdf');
        attachment.setBody([
            SELECT Body FROM Attachment WHERE Id = :attachmentId
        ].Body);

        Messaging.SingleEmailMessage email = 
            new Messaging.SingleEmailMessage();
        email.setToAddresses(new String[] { toEmail });
        email.setSubject('Your Quote from Acme Corp');
        email.setPlainTextBody('Please find your quote attached.');
        email.setFileAttachments(
            new Messaging.EmailFileAttachment[] { attachment }
        );

        Messaging.sendEmail(new Messaging.SingleEmailMessage[] { email });
    }
}

        // Marketing Cloud REST API endpoint
        String endpoint = 'https://[subdomain].rest.marketingcloudapis.com/messaging/v1/email/messages';

        // Build request
        HttpRequest req = new HttpRequest();
        req.setEndpoint(endpoint);
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setHeader('Authorization', 'Bearer ' + getAccessToken());

        // Email payload
        Map<String, Object> payload = new Map<String, Object>{
            'definitionKey' => emailTemplate,
            'recipients' => new List<Map<String, Object>>{
                new Map<String, Object>{
                    'contactKey' => subscriberKey,
                    'to' => attributes.get('email'),
                    'attributes' => attributes
                }
            }
        };

        req.setBody(JSON.serialize(payload));

        // Send request
        Http http = new Http();
        HttpResponse res = http.send(req);

        if (res.getStatusCode() != 202) {
            throw new CalloutException(
                'Marketing Cloud API error: ' + res.getBody()
            );
        }
    }

    Q: How does lead scoring work in Pardot/Account Engagement?¶

    A: Lead scoring automatically assigns point values to prospects based on their demographics and activities, helping sales teams prioritize high-value leads.

    • Numerical value (typically 0-100+)
    • Increases with positive engagement
    • Decreases with negative signals
    • Identifies hot leads

    Grade:

    • Letter grade (A+ to F)
    • Based on fit (demographics)
    • Measures ideal customer match
    • Profile scoring

    Prospect Activities (Behavior):

    • Email opens: +1 point
    • Email clicks: +5 points
    • Form submissions: +10 points
    • Landing page views: +3 points
    • File downloads: +15 points

    • Website visits: +1 point

    • Multiple email opens: Diminishing returns
    • Click-through: Higher value
    • Form completions: Highest value
    • Time on site: Moderate value

    Demographic/Firmographic (Grading):

    • Job title matches: Grade boost
    • Company size in range: Grade boost
    • Industry match: Grade boost
    • Location match: Grade boost
    • Budget authority: Grade boost

            FROM SBQQ__Quote__c

        Map<Id, PricebookEntry> priceMap = new Map<Id, PricebookEntry>();
        for (PricebookEntry pbe : [

        for (ProductRequest prod : products) {

            if (pbe != null) {

                    SBQQ__Quote__c = quoteId,

                    SBQQ__Quantity__c = prod.quantity,
                    SBQQ__PricebookEntryId__c = pbe.Id,
                    SBQQ__ListPrice__c = pbe.UnitPrice
                ));
            }
        }

        if (!lines.isEmpty()) {
            insert lines;
            calculateQuoteWithAPI(quoteId);
        }
    }

public class QuoteDataValidator {

    public static void validateQuotes(Set<Id> quoteIds) {
        Map<Id, List<String>> errors = new Map<Id, List<String>>();

        List<SBQQ__Quote__c> quotes = [
            SELECT Id, Name, SBQQ__Account__c, SBQQ__Opportunity2__c,
                   SBQQ__PriceBook__c,
                   (SELECT Id, SBQQ__Product__c, SBQQ__PricebookEntryId__c
                    FROM SBQQ__LineItems__r)
            FROM SBQQ__Quote__c
            WHERE Id IN :quoteIds
        ];

        for (SBQQ__Quote__c quote : quotes) {
            List<String> quoteErrors = new List<String>();

            if (quote.SBQQ__Account__c == null) {
                quoteErrors.add('Missing Account');
            }
            if (quote.SBQQ__PriceBook__c == null) {
                quoteErrors.add('Missing Price Book');
            }
            if (quote.SBQQ__LineItems__r.isEmpty()) {
                quoteErrors.add('No Quote Lines');
            }

            for (SBQQ__QuoteLine__c line : quote.SBQQ__LineItems__r) {
                if (line.SBQQ__Product__c == null) {
                    quoteErrors.add('Line missing Product');
                }
                if (line.SBQQ__PricebookEntryId__c == null) {
                    quoteErrors.add('Line missing Price Book Entry');
                }
            }

            if (!quoteErrors.isEmpty()) {
                errors.put(quote.Id, quoteErrors);
            }
        }

        // Report errors
        for (Id quoteId : errors.keySet()) {
            System.debug('Quote ' + quoteId + ' Errors:');
            for (String error : errors.get(quoteId)) {
                System.debug('  - ' + error);
            }
        }
    }
}
