name: CI
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Install SFDX
        run: npm install sfdx-cli --global
      - name: Authorize Org
        run: sfdx auth:jwt:grant --clientid ${{ secrets.CLIENT_ID }} --jwtkeyfile server.key --username ${{ secrets.USERNAME }}
      - name: Run Tests
        run: sfdx force:apex:test:run --resultformat human --codecoverage

    Continuous Deployment¶

    Deployment Strategies¶

    Blue-Green Deployment: - Two identical environments - Deploy to inactive (green) - Test green environment - Switch traffic to green - Rollback option (blue)

    Canary Deployment: - Gradual rollout - Small percentage first - Monitor metrics - Increase percentage - Full rollout or rollback

    Rolling Deployment: - Update subsets sequentially - Maintain availability - Gradual rollout - Per-environment

    @isTest
private class AccountServiceTest {
    @isTest
    static void testCreateAccount() {
        // Setup
        Account acc = new Account(Name='Test');

        // Execute
        Test.startTest();
        insert acc;
        Test.stopTest();

        // Verify
        Account result = [SELECT Id, Name FROM Account WHERE Id = :acc.Id];
        System.assertEquals('Test', result.Name);
    }
}

    Best Practices¶

    Development¶

    1. Source Control: Everything in version control
    2. Branching Strategy: Consistent branching model
    3. Code Review: Mandatory peer reviews
    4. Automated Testing: Comprehensive test suite
    5. Continuous Integration: Automated builds and tests

    Deployment¶

    1. Automated Deployments: Minimize manual steps
    2. Validation Deployments: Test before production
    3. Rollback Plan: Always have a rollback strategy
    4. Deployment Windows: Schedule appropriately
    5. Communication: Notify stakeholders

    Monitoring¶

    1. Proactive Monitoring: Don't wait for users to report
    2. Alerting: Set up meaningful alerts
    3. Log Aggregation: Centralize logs
    4. Performance Metrics: Track and optimize
    5. Incident Response: Documented procedures

    DevOps Metrics¶

    DORA Metrics¶

    • Deployment Frequency: How often?
    • Lead Time for Changes: How long from commit to production?
    • Change Failure Rate: What % of deployments cause failures?
    • Time to Restore Service: How quickly recover from failure?

    Additional Metrics¶

    • Code coverage
    • Build success rate
    • Test pass rate
    • Mean time to detection (MTTD)
    • Mean time to resolution (MTTR)
